## 2. 认证系统

关键文件：

- [src/cli/handlers/auth.ts](/Users/bobo/code/claude-code-source-code/src/cli/handlers/auth.ts)
- [src/services/oauth/index.ts](/Users/bobo/code/claude-code-source-code/src/services/oauth/index.ts)
- [src/services/oauth/client.ts](/Users/bobo/code/claude-code-source-code/src/services/oauth/client.ts)
- [src/utils/auth.ts](/Users/bobo/code/claude-code-source-code/src/utils/auth.ts)

支持的路径至少包括：

- Claude.ai OAuth
- Console OAuth
- `ANTHROPIC_API_KEY`
- `CLAUDE_CODE_OAUTH_TOKEN`
- file descriptor 传入 token / key
- `apiKeyHelper`
- Bedrock / Vertex / Foundry 第三方凭据

OAuth 使用 Authorization Code + PKCE：

1. 本地起 callback
2. 生成 `code_verifier` / `code_challenge` / `state`
3. 打开浏览器
4. 获取授权码
5. 换 token
6. 拉 profile
7. 保存账户与组织信息

存储层面：

- Claude.ai OAuth token 走 secure storage
- API key 在 macOS 优先走 Keychain

运行时还处理：

- token 缓存失效
- 多进程 token 变化探测
- 401 后刷新
- lockfile 去重

## 3. 请求层如何识别当前用户

在 [src/services/api/client.ts](/Users/bobo/code/claude-code-source-code/src/services/api/client.ts) 和 [src/services/api/claude.ts](/Users/bobo/code/claude-code-source-code/src/services/api/claude.ts) 中，请求不只带 token，还会带：

- `X-Claude-Code-Session-Id`
- `User-Agent`
- `x-app`
- `device_id`
- `account_uuid`
- `session_id`

因此代码里能直接看到的识别维度至少有三层：

- 凭证
- 账户 / 组织
- 会话 / 设备

补充一点：`device_id` 不是 MAC 地址，而是本地生成并持久化的随机标识。

## 4. 限制与封禁如何落地

这里更准确的说法不是“客户端封用户”，而是“服务端裁决，客户端执行”。

### 认证级拒绝

代码里明确处理了：

- token revoked
- org disabled
- org not allowed
- invalid key

### 组织策略限制

服务端通过 `/api/claude_code/policy_limits` 返回限制，客户端用 `isPolicyAllowed()` 执行。

关键文件：

- [src/services/policyLimits/index.ts](/Users/bobo/code/claude-code-source-code/src/services/policyLimits/index.ts)

### 远程托管设置

服务端通过 `/api/claude_code/settings` 下发 managed settings。

关键文件：

- [src/services/remoteManagedSettings/index.ts](/Users/bobo/code/claude-code-source-code/src/services/remoteManagedSettings/index.ts)

可控制：

- hooks
- 权限规则
- MCP allowlist
- 插件行为
- 登录组织要求

### 强制组织绑定

`forceLoginOrgUUID` 会要求机器只能用指定组织登录。

## 5. 客户端和服务端各管什么

职责边界很清楚：

- 服务端负责裁决  
  token、组织、策略、托管设置
- 客户端负责执行  
  刷新 token、本地缓存、禁用能力、阻断 UI、退出
